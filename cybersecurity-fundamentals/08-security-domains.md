# 08 — Network, Endpoint, Web, Email and Cloud Security

## Network
Use secure device configurations, segmentation, firewalls, ACLs, secure management protocols, VPNs where appropriate, monitoring, and updates. A firewall cannot replace endpoint and identity controls.

## Endpoint
Protect laptops, desktops, and servers with patching, endpoint detection and response, anti-malware, disk encryption, host firewalls, least privilege, application control, and centralized logs.

## Web and application
Enforce authorization on the server, validate input, protect sessions, store secrets safely, maintain dependencies, log security events, and follow a secure development lifecycle. Client-side checks alone cannot enforce access control.

## Email
SPF, DKIM, and DMARC help with sender-domain authentication. Filtering, attachment/link analysis, MFA, user reporting, and incident procedures add protection. No single mechanism makes every message safe.

## Cloud
Security is shared between provider and customer; responsibilities vary by service model. Customers commonly remain responsible for identities, permissions, data, workload settings, configuration, and monitoring. Avoid public storage exposure, excessive permissions, long-lived keys, and unmonitored admin activity.

## Data classification
Classify data by sensitivity and define who may access it, where it may be stored, how it is transmitted, retention periods, and secure disposal.

## Practical
Draw your own lab's endpoint, server, router/firewall, and monitoring system. Mark trust zones, management access, and log collection. Use fictional labels in public documentation.
