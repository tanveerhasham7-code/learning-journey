# 03 — Logs, Telemetry, and Data Sources

## What is a log?
A log is a time-stamped record generated by an operating system, application, security product, network device, or cloud service. Telemetry is broader and includes logs, metrics, traces, process events, network flows, and alerts. Logs are a SOC evidence base. If important systems do not produce useful telemetry, analysts may not see an attack.

## Important data-source families
### Identity and authentication
Directory services, SSO, MFA, VPN, identity providers, and privileged access management. Useful fields include user ID, result, source IP, device, application, authentication method, MFA status, session ID, and risk context.

### Windows
Security, System, Application, PowerShell, Sysmon, Defender/EDR, and directory-service events. Examples include logon success/failure, account changes, group membership changes, process creation, service installation, and scheduled task activity. Event availability depends on audit policy and product configuration; verify event meaning for the source/version.

### Linux
Authentication logs, system journal, audit framework, sudo activity, SSH, process/service logs, package manager logs, and web server logs. Locations vary by distribution. Clues include failed SSH logins, new users, sudo use, modified services, cron changes, and unusual processes.

### Network
Firewall, router, switch, VPN, DNS, DHCP, proxy, IDS/IPS, NetFlow/IPFIX, wireless controller, and packet captures. These help reconstruct connections, name resolution, allowed/blocked traffic, and device addressing.

### Email and collaboration
Mail gateway, message trace, anti-phishing, attachment sandbox, mailbox audit, forwarding rules, OAuth consent, and collaboration audit logs.

### Cloud and SaaS
Cloud control-plane audit logs, object-storage access, workload telemetry, Kubernetes audit, cloud identity, API activity, and SaaS admin logs.

### Applications and databases
Web access/error logs, application authentication, API gateway, database audit, and application security events. Application context is essential for deciding whether a request was expected.

## Anatomy of a useful event
A normalized event may contain timestamp and timezone; event ID/type; source/product; host/asset; user/account; source and destination IP/port; process and parent process; action/result/status; message/raw event; severity; rule ID; and correlation/case ID. Not every source has every field. Preserve the original event alongside normalized fields when policy permits.

## Time is critical
Events may use local time, UTC, or an incorrect device clock. Normalize consistently, record original timezone, and account for clock drift. A timeline without timezone awareness can reverse event order.

## Data quality and visibility
Check whether the source is onboarded and still sending; whether timestamps are correct; whether parsing works; whether host/user identities are consistent; whether duplicates exist; whether retention is sufficient; whether audit categories are enabled; and whether ingestion is delayed or dropping events.

Missing logs do not prove an action did not occur. Collection may be missing, auditing disabled, retention expired, or evidence deleted.

## Windows telemetry
Useful sources include Security auditing, Sysmon process/network/file/registry events when configured, PowerShell operational logging where enabled, and Defender/EDR detections and device timelines. Build an event map for your lab and record enabled audit policies.

## Linux telemetry
Review authentication and privilege events, service start/stop, package installation, SSH access, audit events, and web server activity. Use journal and distribution-specific logs. Protect logs from unauthorized modification and centralize them where possible.

## Practical exercise: log-source inventory
Create a table with source, owner, purpose, key fields, collection method, expected volume, retention, sensitivity, and known gaps. Include a Windows endpoint, Linux server, identity provider, firewall, DNS, email, and cloud audit source.
